# 验证方案：普吉岛 4 天 3 晚文档落地

本文档用于评审，不代表已经运行测试；执行命令见下。

## 1. 验收维度

1. 可执行性：README 与 docs 均能按天执行，包含时间、地点与交通。
2. 一致性：README 的索引锚点、住宿区域与价位、交通价格与 docs 逐项一致。
3. 可追溯性：关键数字（交通价格、3251.5 基线、斯米兰开放期、悬崖咖啡 200 泰铢）标注来源 URL 与检索日期。
4. 负向边界：空 Markdown 链接、空来源标记、错误的检索日期格式、价格不一致不会通过。
5. 变更可回归：已有测试脚本继续覆盖 Day 1–4、预算合计、索引链接等。

## 2. 执行命令与通过标准

- Node.js 18+。
- 运行：
  - `node test/readme.test.js`
  - `node test/usability.test.js`
- 通过标准：每个测试输出 `PASS <名称>`；脚本 exitCode 为 0；不得出现 FAIL。
- 若测试文件中新增断言失败，不允许删除断言或降级为 `assert.ok(true)` 绕过。

## 4. 负向用例与边界

- 空链接：`](https://example.com)` 或 `]()` 必须失败。
- 空来源：`来源：，检索日期 2026-10-06` 必须失败。
- 日期格式：`检索日期 2026/10/06`、`检索日期` 后无值必须失败。
- 交通价格不一致：README 有 `40–80 泰铢` 而 docs 删掉时必须失败。
- 住宿价位不一致：README `300–500` 与 docs `300-500` 写法不一致时需人工确认；测试目前按全角连字符 `–` 检查。
